# Расписание ОшТУ

Быстрое PWA-приложение с расписанием занятий [ОшТУ](https://portal.oshtu.kg/#/schedule).
Ставится на телефон как приложение, показывает пары на сегодня, работает без интернета
и само синхронизируется с сайтом университета.

## Возможности
- Один раз выбираешь семестр → институт → курс → группу, дальше приложение помнит выбор.
- Экран «Сегодня»: текущая пара с прогрессом, сколько осталось, следующая пара. После окончания пар показывает завтрашний день.
- Кнопки ‹ / › и свайпы для перехода между днями, полоса дней недели, вид «Неделя».
- Верхняя и нижняя недели (на сайте ОшТУ ячейка делится линией) чередуются автоматически. Переключить можно в настройках.
- Офлайн: последнее расписание хранится на телефоне, а приложение кэшируется service worker'ом.
- Автосинхронизация: база сверяется с сайтом ОшТУ каждые 20 минут, а приложение проверяет её при каждом открытии. Если сайт ОшТУ упал, отдаётся сохранённая копия.
- **Android-приложение с настоящим виджетом** (`oshtu-schedule.apk`, ссылка в настройках сайта): внутри та же веб-версия, а на рабочий стол добавляется нативный виджет «Пары сегодня» с кнопками ‹ ›, текущей парой и автообновлением.
- Расписание хранится **по неделям**: ОшТУ каждую субботу выкладывает расписание следующей недели, а текущая неделя остаётся как была.
- `widget.html`: веб-виджет для iPhone и приложений-виджетов.
- Ярлыки при долгом нажатии на иконку: «Сегодня», «Завтра», «Неделя».

## Как устроено
```
Телефон (PWA, localStorage + service worker)
   │  RPC oshtu_schedule / oshtu_groups / oshtu_faculties
   ▼
Supabase Postgres ── pg_cron каждые 20 мин ──► http (curl) ──► portal.oshtu.kg/api/*.ashx
   (таблицы oshtu_schedules, oshtu_meta)
```
Сервер ОшТУ поддерживает только старые TLS-шифры, поэтому Edge Functions (Deno/rustls) к нему
не подключаются. Запросы делает сам Postgres через расширение `http` (libcurl + OpenSSL).
SQL лежит в `supabase.sql`.

## Деплой на Render
New → **Static Site** → репозиторий → Build Command: `echo static`, Publish Directory: `.`
(или Blueprint из `render.yaml`).

Обязательно добавь правило в **Redirects/Rewrites**:
`/sb/*` → `https://pzdraaxgzphxennadrlu.supabase.co/*` (действие **Rewrite**).
Приложение ходит в Supabase через свой домен, поэтому работает, даже если провайдер
не пропускает `*.supabase.co`. Если прокси недоступен, запросы идут в Supabase напрямую.
